# Tower Warden

Unreal Engine 5와 C++로 개발한 협동 웨이브 디펜스 액션 게임입니다. 적의 공격으로부터 타워를 지키며 웨이브를 진행하고, 전투와 보스 패턴을 구현했습니다.

이 저장소는 직접 작성한 소스 코드를 소개하는 포트폴리오용 저장소입니다. 외부 에셋을 제외한 코드 검토용 구성이므로, 저장소만으로 게임을 빌드하거나 실행할 수 있는 완전한 프로젝트는 아닙니다.

## 주요 구현

### 전투와 타격 판정

- GAS를 활용한 전투·스킬 기능을 구현했습니다.
- 이전 프레임과 현재 프레임의 무기 소켓 위치 사이를 Sphere Sweep으로 검사하여 빠른 이동으로 인한 타격 누락을 보완했습니다.
- 같은 공격에서 이미 타격한 대상은 `HitActors`로 관리하여 중복 피격을 차단했습니다.
- 서버에서 타격 판정과 데미지를 처리하도록 구성했습니다.

관련 코드: `UpdateWeaponTrace()`

### 적·보스 AI

- 커스텀 C++ FSM으로 적의 상태와 전이를 구성했습니다.
- 일반 적과 보스가 상태 흐름을 공유하고, 보스의 공격 선택을 확장했습니다.
- 보스는 HP 80%·40%를 기준으로 Phase가 변경되며, 해금 Phase·쿨다운·사거리 조건을 만족하는 패턴 중 다음 공격을 선택합니다.
- 순간이동은 뒤쪽 3방향 후보에 대해 캡슐 겹침 검사를 수행하고, 선택한 위치로 이동한 뒤 범위 공격으로 연결했습니다.

관련 코드: `ABaseEnemy`, `SelectNextAttack()`, `FindTPLocation()`

### 데이터 기반 웨이브와 Enemy Pool

- `WaveDataAsset`과 `DataTable`을 사용해 웨이브 구성을 데이터로 관리했습니다.
- 웨이브별 적 종류와 필요 수를 집계하여 풀 크기를 계산하고, 사전 생성한 적을 재사용했습니다.
- 웨이브 진행과 풀 관리는 `UMyWorldSubsystem`, 태그별 적 배치는 `AEnemySpawner`에서 처리하도록 구성했습니다.

관련 코드: `InitializeEnemyPoolInfo()`, `InitializePool()`, `UMyWorldSubsystem`, `AEnemySpawner`

### 서버 시간 기준 UI 동기화

- 서버가 웨이브 카운트다운 종료 시각을 계산하고 `AMyRPGGameState`를 통해 복제합니다.
- 클라이언트는 서버 시간 기준으로 남은 시간을 계산해 표시합니다.
- `GameState → LocalPlayerSubsystem → HUD` 구독 구조로 게임 상태와 UI 갱신을 분리했습니다.
- 게임오버는 복제 상태와 RepNotify를 통해 전달하도록 구성했습니다.

관련 코드: `StartWaveCountdown()`, `RefreshCountdown()`, `AMyRPGGameState`, `UMyWaveUISystem`

## Enemy Pool 성능 측정

2026.11.13에 수집한 풀링 OFF·ON 각 3개 CSV 기록을 비교했습니다. 지표는 각 기록의 **`GameThreadTime` 최대값**이며, 값이 낮을수록 해당 기록에서 관측된 게임 스레드 최대 지연이 작습니다.

| 기록 | 풀링 OFF | 풀링 ON |
| --- | ---: | ---: |
| 추가 1회 | 123.57 ms | 73.00 ms |
| 추가 2회 | 118.17 ms | 51.98 ms |
| 추가 3회 | 115.46 ms | 43.81 ms |
| 회차별 최대값의 평균 | **119.06 ms** | **56.26 ms** |

이번 기록에서 회차별 최대값의 평균은 약 **52.7% 감소**했습니다. OFF 3회에서는 `ActorSpawning`에 최대 69.60~72.49 ms가 기록됐습니다.

### 측정 환경과 해석 범위

- Unreal Engine 5.7.4 · Development · Windows · 1914 × 992
- OFF 기록은 적 수가 0에서 50으로 증가하며, ON 기록은 적 52개가 사전 생성된 상태입니다. 기록된 액터 수가 활성 전투 개체 수와 동일하다는 뜻은 아닙니다.
- 측정 길이와 전투 전후 구간 비중이 달라 전체 구간 평균 FPS는 직접 비교하지 않았습니다. 최대값도 기록 구간의 영향을 받습니다.
- 게임 스레드 시간에는 대기 등 다른 영향도 포함될 수 있으므로, 52.7%를 순수 생성 비용의 감소율이나 일반적인 FPS 향상률로 해석하지 않습니다.
- 풀링의 사전 생성 비용은 위 전투 구간 비교와 별도로 고려해야 합니다.

이전 포트폴리오에는 OFF 124.4 ms / ON 52.4 ms의 측정 결과도 있습니다. 현재 원본 CSV를 재확인하지 못한 참고값이므로 위 3회 평균과 감소율 계산에는 포함하지 않았습니다.

## 확인 범위

전투와 보스 패턴은 플레이 시연으로, 웨이브 상태 공유는 2인 Listen Server 환경에서 확인했습니다. 재접속 처리는 현재 구현·검증 범위에 포함하지 않습니다.

코드 검토 시에는 전투 판정, 웨이브 데이터 처리, 풀 생성·재사용, 서버 시간 기반 카운트다운 순서로 확인할 수 있습니다. 위 클래스·함수명은 포트폴리오에 제시된 구현을 기준으로 작성했습니다.
